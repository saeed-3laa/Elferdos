# مخزن الفردوس — نظام طلبات الجملة

تطبيق عربي RTL لطلبات الجملة داخل الإسكندرية باستخدام Next.js App Router وTypeScript وSupabase.

## حالة المشروع

النسخة المحلية تنفذ الكتالوج والحسابات والعناوين والصور والتوافر اليدوي «متوفر/غير متوفر»، والسلة وإرسال الطلبات وحالاتها والتحصيل والرد، والعروض والأسعار الخاصة، واستيراد وتصدير Excel والتقارير وصلاحيات الموظفين واسترجاع الحساب إداريًا. لا يوجد إدخال أرصدة مخزن أو حجزها أو خصمها؛ كميات الطلب والتعبئة والفاتورة تبقى محسوبة. الأسعار والتوافر والصلاحيات تتحقق على الخادم وقاعدة البيانات. الإضافة للسلة لا تفتح البار الجانبي تلقائيًا. اختُبرت محليًا؛ النشر واختبارات الحمل والنسخ البعيد وتهيئة المالك ومتطلبات الأمان المتبقية موثقة في docs/test-report.md وdocs/security-audit.md.

## تشغيل سريع

```powershell
npm ci
Copy-Item .env.example .env.local
npm run dev
```

افتح http://localhost:3000. لتوصيل الكتالوج راجع دليل الإعداد؛ لا توجد بيانات عمل حقيقية أو مفاتيح مضمنة. تحتاج خدمات Supabase المحلية إلى Docker Desktop.

على جهاز التطوير الحالي، خدمات Supabase تعمل والكتالوج متصل بالبيانات المحفوظة محليًا؛ لا تستخدم reset لمسحها. اختبارات المتصفح تنشئ سجلات اختبار مستقلة وتنظفها. لإعادة تشغيل البيئة استخدم `npm run db:start:core`، وللتحقق استخدم `npm run test:e2e:local`.

العملاء يدخلون بالموبايل، وفريق الإدارة ببريد موثّق من `/staff/login`، مع إعداد TOTP من حساب الموظف. حساب المالك الحالي في مرحلة ربط البريد؛ لا تُفعّل سياسة الإنتاج الإلزامية قبل إثبات الملكية وربط تطبيقه. رسائل نسخة Docker محلية في Mailpit، وليست رسائل Gmail فعلية.
