# تشغيل أساس المشروع

## المتطلبات

- Node.js 24 LTS وnpm. الإصدارات الدقيقة للحزم محفوظة في package-lock.json.
- Docker Desktop بوضع Linux Containers مطلوب لتشغيل خدمات Supabase المحلية كاملة. اختبارات PGlite لا تحتاج Docker.
- تم اختيار TypeScript 6 لأن أدوات التحليل الحالية لا تدعم TypeScript 7. يستخدم المشروع ESLint 10 وقواعد Next.js وTypeScript مباشرة لتجنب إضافات أقدم لا تدعم ESLint 10.

## تشغيل الواجهة

```powershell
npm ci
Copy-Item .env.example .env.local
npm run dev
```

افتح http://localhost:3000. عند غياب إعداد Supabase تظهر حالة تجهيز صريحة، دون منتجات وهمية أو استقبال طلبات. الخط العربي مضمن محليًا ولا يحتاج Google Fonts وقت البناء.

## Supabase محلي

شغّل Docker Desktop أولًا، ثم:

```powershell
npm run db:start
```

لو تنزيل كل الخدمات ثقيل على جهاز التطوير، استخدم `npm run db:start:core` لتشغيل قاعدة البيانات وAuth وPostgREST وStorage والبوابة. هذا الوضع يشغل صور المنتجات، ويستبعد Studio وRealtime والخدمات الإضافية. لتغيير مجموعة الخدمات أوقف البيئة المحلية أولًا باستخدام `db:stop` دون حذف البيانات ثم شغّل الوضع المطلوب. ترحيل الصور ينشئ bucket باسم `product-images`، ويحتاج Storage قبل اختبار الرفع. التفاصيل والصيانة في [دليل الإدارة](admin.md).

انسخ عنوان API والمفتاح العام المحلي إلى متغيري `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` في `.env.local`. يمكن استخدام مفتاح anon المحلي الذي تعرضه CLI بدل publishable. المفتاح `service_role` يخص الخادم وأوامر الإدارة فقط؛ لا تضعه في أي متغير يبدأ بـ `NEXT_PUBLIC_`.

بدل النسخ اليدوي، إذا لم يوجد `.env.local` بعد تشغيل الخدمات، نفذ `npm run db:env`. الأداة تقرأ حالة البيئة المحلية وتكتب المفاتيح في الملف المتجاهل من Git دون عرضها، وترفض الكتابة فوق ملف موجود. ثم `npm run test:local-auth` لاختبار الخدمات الحقيقية.

المخطط الأول ينشئ الحسابات والصلاحيات والمناطق والمنتجات ووحدات الجملة والمخزون والتدقيق وRLS. بيانات seed خيالية ومعلّمة كذلك. لا أسعار توصيل أو حساب إنستا باي حقيقيين مفترضين.

`npm run db:reset` يعيد إنشاء **قاعدة التطوير المحلية ويمحو بياناتها** ويطبق الترحيلات وseed. استخدمه فقط عندما تقصد إعادة بيانات بيئة التطوير. `npm run db:stop` يوقف الخدمات.

لتجربة خدمة Auth الفعلية، ضع المفتاح المحلي للخادم في `.env.local` ثم شغّل:

```powershell
node --env-file=.env.local scripts/test-local-auth.mjs
```

بعد نجاح اختبار الخدمات نفذ `npm run test:e2e:local` لاختبار الكتالوج المتصل بالمتصفح على الكمبيوتر ومحاكاة أندرويد. هذا الاختبار يرفض أي عنوان Supabase غير محلي، ويحتاج بيانات seed الخيالية وخدمات التطوير قيد التشغيل.

لاختبار البناء الإنتاجي نفسه شغّل `npm run build` أولًا، ثم عيّن `E2E_PRODUCTION=1` في بيئة أمر `npm run test:e2e:local`. هذا يشغل `next start` بدل خادم التطوير، ويحتاج مفتاح حدود المحاولات الموثق في دليل الحسابات.

الاختبار يرفض أي عنوان غير localhost/127.0.0.1، وينشئ مستخدمين مؤقتين ثم ينظفهما. يتحقق من التسجيل والدخول بالموبايل وعزل البيانات وتغيير كلمة المرور إداريًا. لا يختبر شاشة استرجاع أو إبطال جميع الجلسات؛ هذه ضمن مرحلة الحسابات.

`auth.sms.enable_confirmations = false` في الإعداد المحلي يعطل تأكيد الموبايل. لا يوجد اتصال بمزود SMS حقيقي. إصدار CLI الحالي يعطل تسجيل الهاتف إذا كانت كل كتل مزودي الرسائل غير مفعلة، لذلك يتضمن config.toml كتلة Twilio **محلية فقط** بقيم باطلة مقصودة، لتشغيل الهاتف وكلمة المرور مع التأكيد معطلًا. هذه ليست بيانات اعتماد ولا خدمة رسائل متصلة. لا تستخدم OTP أو استرجاع عبر SMS بهذه البيئة، ولا تنقل هذه الكتلة إلى مشروع مستضاف. التسجيل بكلمة المرور هنا لا يرسل رسالة ولا يعرض ادعاء إرسالها.

هذا الحل خاص بالتطوير ويجب التحقق من إعداد الهاتف مستقلًا على بيئة الاستضافة. المصادر: [توثيق Supabase للمصادقة بكلمة المرور](https://supabase.com/docs/guides/auth/passwords)، و[تحقق CLI من مزود SMS](https://github.com/supabase/cli/blob/develop/apps/cli-go/pkg/config/config.go).

## إنشاء المالك

أنشئ مستخدم هاتف في بيئة Supabase المطلوبة بكلمة مرور تختارها أنت، وتأكد من وجود profile مطابق. ضع UUID في `BOOTSTRAP_OWNER_USER_ID` ومفتاح الخادم في المتغير المخصص، ثم:

```powershell
npm run admin:bootstrap
```

الأداة تعين OWNER لحساب قائم ونشط وتسجل العملية؛ لا تنشئ كلمة مرور ثابتة. لا تشارك `.env.local` ولا مخرجات CLI التي تحتوي مفاتيح. حذف بيانات التشغيل ليس جزءًا من أداة إنشاء المالك.

## الفحوصات

بعد تحديث المشروع طبّق الترحيلات الإضافية على التطوير المحلي بـ `npx supabase migration up --local`؛ لا حاجة لمسح القاعدة لتحديثها. قبل تشغيل حسابات الويب في production يجب ضبط `SUPABASE_SERVICE_ROLE_KEY` و`AUTH_RATE_LIMIT_SECRET` للخادم فقط. دليل [الحسابات](customer-accounts.md) يشرح الحدود وإعداد الوكيل الموثوق. لا تستخدم مفتاح الخادم في المتصفح.

```powershell
npm run lint
npm run typecheck
npm test
npx playwright install chromium
npm run test:e2e
npm run build
```

Vitest يشغل قواعد العمل ومحرك PostgreSQL مدمجًا عبر PGlite؛ مخطط auth والأدوار في الاختبار تجهيزات تحاكي سياق Supabase. لا تعني هذه الاختبارات تحققًا من خدمة Auth أو PostgREST أو التزامن بين اتصالات متعددة. Playwright يشغل واجهة حقيقية على منفذ 3100 مع تعطيل إعداد Supabase في عملية الاختبار عمدًا لاختبار حالة التجهيز؛ لا يدعي اختبار دورة الطلب.

## الترحيل إلى بيئة اختبار مستضافة

أنشئ مشروع Supabase مستقلًا للتطوير أو المعاينة، وطبق ملفات `supabase/migrations` بالترتيب بعد مراجعتها. لا تستخدم seed على الإنتاج. اضبط مزود الهاتف وكلمة المرور وسياسة التأكيد وفق الإعداد الموثق، ثم شغّل اختبارات تكامل مخصصة للبيئة قبل تفعيل العملاء.

جهز مشروع Vercel متصلًا بالمستودع، وأضف متغيرات البيئة الخاصة بكل بيئة على حدة. البناء `npm run build`. لا تجعل بيئة المعاينة تتصل بقاعدة الإنتاج. الواجهة الحالية للكتالوج فقط؛ نشرها لا يعني جاهزية استقبال طلبات.

## النسخ الاحتياطي والتعافي

قبل أول تشغيل حقيقي: حدد RPO/RTO، فعّل نسخة دورية لقاعدة البيانات وفق إمكانات الاستضافة، واحتفظ بنسخ منفصلة لملفات الصور مع سياسة وصول خاصة. اختبر الاستعادة إلى مشروع اختبار مستقل وتحقق من الأرصدة والحجوزات والطلبات والصلاحيات قبل اعتماد الخطة. لم تُنفذ استعادة فعلية في مرحلة التأسيس. الترحيلات والنسخ الاحتياطية لا تُطبق على الإنتاج آليًا بواسطة CI الحالي.

## معالجة المشاكل

- «الكتالوج قيد التجهيز»: راجع عنوان Supabase والمفتاح العام ثم أعد تشغيل Next.js.
- «تعذّر تحميل المنتجات»: تحقق من وصول API وتطبيق الترحيل الذي ينشئ `browse_catalog`. لا تُعرض تفاصيل أخطاء قاعدة البيانات للزائر.
- Docker pipe غير موجود: شغّل Docker Desktop وانتظر جاهزية Linux engine قبل `db:start`.
- Playwright لا يجد المتصفح: نفذ أمر تثبيت Chromium مرة واحدة؛ الاختبارات تحتاج صلاحية تشغيل عمليات فرعية.
- تعارض تحديث المنتج أو التوافر اليدوي: أعد قراءة النسخة الحالية؛ لا تتجاوز رقم النسخة. لا توجد شاشة تحديث مخزون.
- البحث الحالي يطابق الكلمات العربية بعد تطبيع الحروف والحركات، أو كود المنتج كاملًا؛ البحث الجزئي والفلاتر الإضافية ضمن المرحلة التالية.
