نجح lint وTypeScript قبل المراجعة الأخيرة، ونجح بناء إنتاج معزول داخل `.work/availability-build` دون استبدال `.next` الذي تستخدمه المعاينة الحالية. أعيدت ملفات إعداد البناء إلى وضعها المعتاد. نجحت مجموعة اختبارات القواعد/SQL 304 اختبارات في 12 ملفًا، قبل إضافة اختبار حفظ التاريخ الأخير. هذه المجموعة تشمل 17 حالة تنفيذ فعلي للترحيل 028 داخل معاملات PGlite معزولة: الطلب برصيد تاريخي صفر وقديم، كل ترتيبات الكتالوج، المنتج غير المتوفر، صلاحيات التعديل وتعارض النسخ، عدم إنشاء سجل مخزون جديد، التلاعب بالسعر والكمية، الإلغاء، تعديل الكميات، التسليم والتحصيل والمرتجع، رفض RPC واستيراد المخزون القديم وعزل العملاء. الحالات الأقدم تختبر مخطط 001–027 قبل الترقية عمدًا؛ ليست شهادة تشغيل 028 عبر Supabase الحقيقي.

**لم يُطبق 028 على قاعدة التطوير الفعلية بعد.** فشل تشغيل `.work/apply-manual-availability.mjs` قبل التنفيذ لأن مراجعة الموافقة التلقائية لم تتم بسبب حد الاستخدام. هذا فشل في خدمة المراجعة وليس حكمًا بعدم أمان الإجراء، ولم يُلتف على المنع بوسيلة أخرى. لذلك لم تنفذ مقارنة البصمات على البيانات الفعلية ولم تُعد رحلات المتصفح المتصلة بعد 028. ملفات اختبارات المتصفح عُدّلت للمتطلبات الجديدة، وتظل غير منفذة. نتائج 70 رحلة في الأقسام السابقة لا تخص هذا التغيير. لا تُعد المعاينة الحالية على 3000 محدثة بالكامل حتى تطبيق الترحيل والبناء وإعادة التشغيل والتحقق المتصل.

حدود المرحلة: بيانات التصدير تُقرأ أثناء التحميل ولا تمثل snapshot ثابتًا. لم يثبت هذا الاختبار قدرة تنزيل ملايين السجلات أو تحمل الاستضافة؛ يلزم قياسها على staging مع حجم واقعي، وقد يلزم worker وحدود تزامن عند النمو. كل المرتجع المعتمد يعاد للمخزون وفق طلب صاحب النظام، بما فيه التالف إن أُدخل كمرتجع؛ لا يوجد مسار استبعاد تالف. النقد لا يعتبر مردودًا إلا بحركة رد حقيقية. لم تختبر الاستعادة مجددًا بعد 027؛ تجربة 023 السابقة لا تثبت النسخ المجدول البعيد. لم تفعّل سياسة MFA العامة أو توثق بريد المالك الحقيقي أو تغيّر إعدادات إنتاج. الرفع إلى GitHub والنشر ما زالا متوقفين لحين تحديد الحساب الصحيح والاستضافة، ولم يعمل GitHub Actions على GitHub.

إعادة التصدير النهائية بعد تحسين التعافي: **٤/٤ ناجحة**، مرتان على كل مقاس باستخدام عاملين متوازيين، دون إعادة تلقائية للاختبار الفاشل. فُتح الملفان وتحققت كل معرفات المنتجات التجريبية، وسعر الوحدة ١٠٠ جنيه، ورصيد ٤٨ قطعة، ومحجوز صفر، ومتاح ٤ وحدات جملة من ١٢ قطعة. نجح آخر بناء وlint وTypeScript وفحص الأسرار؛ أُعيد تشغيل المعاينة على 3000. لا توجد اختبارات فاشلة باقية في الإعادات النهائية المنفذة، مع حدود الاستضافة المذكورة أعلاه.

### ما تغطيه الرحلات الحساسة

إنشاء موظف ببريد بلا بيانات محل أو هوية هاتف للدخول، رفضه قبل تأكيد البريد، استهلاك رابط تأكيد خيالي داخل المتصفح، تغيير كلمة مروره مع رفض الحالية الخاطئة، تغيير رقم التواصل بواسطة المالك، إبطال الجلسات والتعطيل. العميل لا يرى تغيير الدور ولا يكتسبه من metadata أو RPC. ترحيل حساب إداري قديم وتهيئة أول مالك بالهاتف جُرّبا عبر رسائل وصلت إلى Mailpit المحلي؛ قبل التأكيد لا تمنح التهيئة الجديدة صلاحيات الإدارة، والرابط المستخدم لا يقبل الإعادة.

جرّب المتصفح TOTP فعليًا وحصل على AAL2. العامل الموثّق يفرض التحدي على الدخول اللاحق حتى قبل سياسة الإلزام العامة. نجحت محاولة إعادة طلب تغيير كلمة المرور الملتقط بجلسة نفس الموظف عند AAL1 في إثبات الرفض، ورفض المزود حذف العامل الموثّق عند AAL1 بكود HTTP 422 وinsufficient_aal. لا يعتمد الاختبار على وجود أي خطأ عشوائي فقط.

اختُبر تجاوز الواجهة بطلب Server Action ملتقط من عميل، مع إجراء مسموح كضابط إيجابي وطلب Origin عدائي؛ مُنع التعديل، ولم ينشأ حساب من المحاولتين المرفوضتين. Next يعيد 500 مع Invalid Server Actions للـOrigin العدائي؛ التحقق يشمل عدم حدوث كتابة، وليس كود الخطأ وحده. فُحصت CSP بحقن سكربت في استجابة HTML الأصلية، وتغيّر nonce، وno-store، وحجب البحث/التصدير الخاص، واستبعاد الموظفين من ملف العملاء، ورفض التصدير المتكرر بـ429.

تغطي الرحلات أيضًا حجز آخر كمية بالتنافس، الأسعار غير القابلة لتلاعب المتصفح والخصم الأفضل دون تكديس، تعديل الطلب الجاهز وإشعار العميل فقط، والتحصيل/التسليم دون تكرار مال أو مخزون، وصور المنتجات وExcel والصلاحيات والعناوين. اختُبرت محاذاة مربع المتاح مع النص بفارق أقل من ٤ بكسل.

### إخفاقات صُححت قبل النتيجة النهائية

لم تُحذف اختبارات الأمان الفاشلة: فُصلت صناعة ملف الاختبار عن وحدة server-only باستعمال قالب التنزيل الحقيقي، وصُحّح تعريف Buffer الاختباري لـExcelJS. حدّثت خدمة Auth المحلية بعد أن أظهرت رسالة قالبًا قديمًا بعنوان المنفذ 3000. محدد سجل التدقيق قُيد بالنسخة المرئية لأن React/Next قد يحتفظ بنسخ مخفية خلال التنقل. اختبار رفض الدخول ينتظر الرد ثم رسالة الرفض المرئية بنافذة ٣٠ ثانية؛ انتظار غلق stream كامل لم يكن معيارًا مناسبًا لهذه الاستجابة. وصُحّح افتراض HTTP 403 لإزالة MFA إلى رد المزود الفعلي 422 مع فحص insufficient_aal. لم تُخفّف صلاحيات الخادم أو تُعطّل CSP/MFA لتمرير أي اختبار.

### حدود النتيجة

لا توجد بيئة إنتاج أو SMTP حقيقي تم اختبارهما. Mailpit يلتقط الرسائل محليًا ولا يثبت ملكية Gmail. سياسة الإلزام لجميع الإداريين ما زالت مؤجلة حتى تأكيد المالك بريده وربط جهازه؛ الموظف الذي فعّل عاملًا موثّقًا يحتاج AAL2 بالفعل. يلزم ضبط المشروع المستضاف وTLS وحدود المزود والمراقبة ونسخ قاعدة البيانات وStorage الدورية والبعيدة وتجربة استعادتها. لم يُجر فحص هجومي أو تحميل على إنتاج، ولم يُشغّل سير GitHub على GitHub بعد. محاكاة Pixel 7 ليست هاتفًا فعليًا. راجع تقرير الأمان ودليل التشغيل للمتبقي بالتفصيل.

ما يلي سجل التحقق السابق، محفوظ لتتبع المراحل؛ النتيجة أعلاه هي الأحدث.


تحديث تفاعلات الشراء — ٢٨ أكتوبر ٢٠٢٦: نجح البناء وlint وTypeScript و٢١٦ اختبار قواعد/SQL، ثم المجموعة المتصلة الكاملة ٤٦ اختبارًا و٨ أساسية على الكمبيوتر والموبايل. توسع اختبار العروض ليغطي حركة الكارت دون تغيير ارتفاعه، والكيبورد، والحد الأدنى لوحدة البيع، والسلة الجانبية وتعديل الكمية وحفظها والانتقال لمراجعة الطلب والحذف والعودة للتركيز بـEscape وحفظ عرض القائمة. نجح اختبار الموبايل المستهدف أولًا وفشل محدد الكمبيوتر بسبب نسختي DOM ظاهرة ومخفية أثناء تنقل Next.js؛ قُيد المحدد بالواجهة الظاهرة ثم نجحت المجموعة الكاملة. عولج فشل البناء الأول الناتج عن فحص ملفات متصفح مؤقتة مقفولة داخل .work بقصر Tailwind على src واستبعاد .work من ESLint وGit. لم تُعدّل بيانات المستخدم ولا SQL أو قواعد التسعير والحجز. روجعت صور الشبكة والقائمة والسلة على المقاسين، والمعاينة تعمل على 3000.

## آخر النتائج

إصلاح ثبات نموذج دور الموظف: أعيد إنتاج الحالة حيث تنجح كتابة ORDER_STAFF في قاعدة البيانات بينما تعود القائمة المرئية إلى VIEWER بعد الحفظ. أصبحت حقول الدور والتفعيل مضبوطة بحالة React، مع إرسال الإجراء داخل transition دون إعادة الضبط الأصلية للنموذج، وإعادة تهيئة الحقول عند تغير بيانات الخادم. لم تتغير صلاحيات SQL أو أدوار الحسابات الحقيقية. نجحت فحوص lint وTypeScript والبناء، ثم ٤ اختبارات متصفح مستهدفة على الكمبيوتر والموبايل: اختيار الدور وحفظه مرتين وإعادة تحميل الصفحة، وحفظ تعطيل صلاحية الموظف دون تغيير دوره، ورحلة الإدارة التي تعين موظف طلبات وتراجع صلاحياته فعليًا. لم تُعد المجموعة الكاملة في هذا الإصلاح.

تحديث التصميم: أضيف نظام بصري موحد للمتجر والحساب والسلة ولوحة الإدارة، مع بطاقات منتجات وأقسام وسلة بعداد فعلي وتنقل للموبايل وقائمة إدارة جانبية. نجح البناء وlint وTypeScript و١٩٤ اختبار قواعد. شُغلت مجموعة المتصفح المتصلة كاملة (٣٨ اختبارًا): نجح ٣٧ وكشف اختبار Excel للموبايل تداخلًا ناتجًا عن ارتفاع نسبي لبطاقات النماذج. أزيل الارتفاع النسبي، ثم نجحت الاختبارات الستة المتأثرة للإدارة والتسعير وExcel والتقارير على الكمبيوتر والموبايل؛ لم تعد المجموعة الكاملة بعد هذا الإصلاح الموضعي. نجحت اختبارات الواجهة الأساسية الثمانية أيضًا. روجعت صور المتجر والإدارة والسلة ومعاينة Excel بصريًا، وتأكد عدم تمدد الصفحة أفقيًا وإمكانية الضغط على اعتماد الاستيراد. تقارير الاختبار المتصلة والأساسية أصبحت في مجلدين منفصلين حتى لا تمحو إحداهما صور الأخرى.

تحديث عنوان المحل: الترحيل 015 ربط عنوان الحساب بعنوان توصيل محفوظ عند تطابق منطقة متاحة، مع تجهيز الحسابات القديمة دون تكرار عنوان مطابق أو استبدال عنوان بديل اختير افتراضيًا. عند تعذر تحديد المنطقة، يُطلب اختيارها وحدها مع نسخ العنوان من الحساب على الخادم. نجح البناء و**١٩٤ اختبار قواعد وSQL**. نجحت ٤ رحلات متصفح لإدارة العناوين وإرسال الطلب على الكمبيوتر والموبايل. فشلت ٤ رحلات جديدة أولًا بسبب محدد اختبار يبحث عن النص الداخلي للقائمة بدل اسمها المتاح؛ بعد تصحيح المحدد نجحت الرحلات الأربع لاختيار عنوان التسجيل تلقائيًا وثباته بعد إعادة التحميل وتأكيد المنطقة دون إعادة كتابة العنوان. لم يتغير كود التطبيق بين هذين التشغيلين. لا تمثل النتائج إعادة تشغيل مجموعة المتصفح الكاملة.

تحديث اقتراحات البحث: طُبق الترحيل 014 دون مسح البيانات، ونجحت فحوص lint وTypeScript والبناء و**١٨٨ اختبار قواعد وSQL**. نجحت **٦ اختبارات متصفح مستهدفة** على الكمبيوتر والموبايل للبحث المعتاد والاقتراحات من أول حرف والاختيار بالكيبورد والضغط وفتح المنتج والعميل وحجب البيانات الخاصة. روجعت صورة الاقتراحات على الموبايل وشُغلت المعاينة الجديدة على منفذ 3000. لم تُعد مجموعة المتصفح الكاملة في هذا التحديث؛ نتائجها السابقة أدناه.

- npm run lint: ناجح دون أخطاء أو تحذيرات، بما فيها سكربتات الصيانة.
- npm run typecheck: ناجح مع توليد أنواع المسارات وفحص TypeScript strict.
- npm test: **١٨٢ اختبارًا ناجحًا في ٧ ملفات**.
- npm run build: ناجح؛ يشمل الحسابات والكتالوج والإدارة والطلبات وExcel والتقارير.
- E2E_PRODUCTION=1 مع npm run test:e2e:local: **٢٨ اختبارًا ناجحًا** على Chromium للكمبيوتر ومحاكاة Pixel 7، نحو دقيقة و٤٧ ثانية. تستخدم الخدمات الحقيقية وبيانات خيالية مؤقتة وتنظف سجلاتها المحددة.
- npm run test:e2e: **٨ اختبارات ناجحة** في نحو ٤٠ ثانية؛ ببيئة Supabase فارغة عمدًا لاختبار حالات الإعداد والواجهة والسلة للزائر.
- npm audit: صفر ثغرات معروفة في آخر فحص بعد قفل ExcelJS واستبدال اعتماده الفرعي uuid بإصدار 11.1.1 المتوافق مع require. ليست ضمانًا أمنيًا دائمًا.
- نسخة الإنتاج المحلية على http://127.0.0.1:3000 تعيد HTTP 200 وتحتوي رابط السلة.
- أسرار .env.local والحزم والبناء وتقارير الاختبارات مستبعدة من Git. فحص حزم JavaScript للمتصفح لم يجد مفتاح الخدمة أو سر HMAC، دون طباعة قيمهما.

## تغطية القواعد والبيانات

تشغل PGlite الترحيلات الحقيقية وseed بتجهيز محدود لمخطط Auth وclaims والجلسات. تشمل RLS وعزل العملاء ومنع الكتابة المباشرة وتجاوز النسخ والصلاحيات، الموظفين والحساب المعطل والعناوين والمناطق، البحث العربي والترقيم والأكواد والجرد وتقادم المخزون، والصور وتوقيعها وإعادة ترميزها وتعارضها، ووحدات الجملة والمال بالقروش والتقريب.

تغطي الأسعار أقل قاعدة مؤهلة دون تكديس، العميل والكمية والنطاق والزمن، وعدم تسريب الأسعار الخاصة. تغطي الطلبات مقارنة العرض الحالي وتجميع مخزون المنتج عبر وحدات مختلفة، ومنع التكرار واختلاف مدخلاته، والحجز والإلغاء والتسليم مرة واحدة، وثبات نسخ الأسعار والعناوين، والمجاني عند أكبر من ٢٠٠٠ فقط.

تغطي المدفوعات القبض والرد والحدود ومنع التكرار ومنع إلغاء طلب مدفوع قبل رد صافي المقبوض. تشمل الاسترجاع وإبطال الجلسات، وقيود المالك والأذونات، والاستيراد الذري والتراجع عند الخطأ وتعارض المخزون وإعادة الاعتماد، والتقارير وحدود أيام القاهرة والتجميع بالهوية الثابتة رغم تغيير الاسم.

اختبارات Excel تقرأ XLSX فعليًا وتشمل RTL والأرقام والتصدير وإعادة القراءة وحدود الصفوف والحجم وفحص ZIP ورفض الصيغ والقيم المركبة. تحفظ النصوص كنصوص دون تفسيرها كصيغ.

## الخدمات والمتصفح

خدمات Supabase المحلية: PostgreSQL وAuth وPostgREST وKong وStorage. الترحيلات 001–013 مطبقة دون مسح القاعدة. اختبار Auth السابق تحقق من التسجيل والدخول بالهاتف وكلمة المرور الخاطئة والعزل والتغيير الإداري. لا SMS حقيقي مرسل؛ إعداد الهاتف المحلي التجريبي لا ينقل للإنتاج.

تغطي المجموعة المتصلة الحساب والملف والعناوين والجلسات، إدارة المناطق والأقسام والمنتجات والوحدات والجرد والأرشفة والتدقيق، الأكواد المتزامنة، رفع صورة وتطبيعها وقراءة رابطها واستبدالها وحذفها ومنع الكتابة المباشرة، وقيود العميل والمدير والمشاهد.

تغطي أيضًا شراء وحدتي جملة ومراجعة السلة والإرسال وانتقالات الإدارة والتسليم والتحصيل وتصدير الطلب، قواعد عامة وخاصة، تعيين موظف، معاينة ملف مخزون دون تعديل ثم اعتماده وقراءة تقرير Excel. تجربة تنافس فعلية لعميلين على آخر كرتونة أعطت فائزًا واحدًا وحجزًا واحدًا وإعادة إرسال آمنة، ثم تحرير الحجز بالإلغاء. وتجربة استرجاع فعلية رفضت JWT القديم وكلمة المرور القديمة وقبلت الجديدة.

أصلح التحقق تسميات حقول واختيار العناصر المرئية عند وجود نسخ DOM مخفية من Next/React؛ نجحت المجموعة الكاملة بعد الإصلاح. محاكاة Pixel 7 لا تعادل اختبار هاتف فعلي.

## استعادة قاعدة البيانات

نجح scripts/check-database-restore.mjs: pg_dump بصيغة custom داخل حاوية التطوير، ثم استعادة إلى قاعدة جديدة مولدة لهذه العملية وفحص الجداول والقيود وإزالة موارد التجربة المحددة. النسخة المستعادة: ٢ ملف مستخدم و٤ منتجات وصفر طلبات و٢٦ مفتاحًا أجنبيًا عامًا. لا تغير القاعدة الأصلية ولا تنتج نسخة احتياطية دائمة.

احتاجت الاستعادة دور الصيانة المحلي supabase_admin لإعدادات دوال المخططات المدارة التي لا يستطيع postgres استعادتها؛ بقيت ملكيات العناصر محفوظة. ملفات Storage تحتاج نسخًا واستعادة منفصلين لم يختبرا بعد.

معاينة تنظيف الصور السابقة نجحت بصفر ملفات مؤهلة. الحذف الجماعي لم ينفذ بعد رفض المراجعة الآلية له، ولا توجد جدولة. حذف صور الاختبار المحددة والاستبدال والحذف العادي من الشاشة اختبرت بنجاح.

## فحص نمو الكتالوج

scripts/check-catalog-scale.mjs ينشئ ١٠ آلاف منتج ووحدة خيالية داخل معاملة تلغى، وينفذ ١٥٠ استعلامًا تسلسليًا: ٥٠ لكل حالة. آخر قياس بعد فهارس التصفية والترتيب:

- البحث العربي مع المتاح: متوسط ٥٣٣٫٢٧ ms، وp95 نحو ٨٢٢٫٣٨ ms، وأقصى ٢٧٣٤٫٥٣ ms.
- أول صفحة لقسم: متوسط ٩٧٫٨١ ms، وp95 نحو ١٨٦ ms، وأقصى ٢١٥٫٣١ ms.
- SKU كامل: متوسط ٢٠٫٦ ms، وp95 نحو ٣٥٫٢٣ ms، وأقصى ٦٦٫٢٢ ms.

هذه استعلامات تسلسلية على جهاز التطوير وبيانات داخل معاملة دون إحصاءات إنتاج ممثلة؛ ليست HTTP أو حركة مستخدمين موزعة. تفاوت البحث العربي بين التشغيلات يحتاج قياسًا أوسع. تعطيل JIT التجريبي لم يثبت تحسينًا ولم يغير إعدادًا عامًا. لا ضمان سعة أو زمن استجابة.

## المتبقي وحدود التحقق

لم ينشر التطبيق أو تطبق الترحيلات على استضافة. لم تختبر نسخ دورية أو استعادة الصور أو مراقبة إنتاج أو HTTP متزامن ونقطة التشبع. سير GitHub Actions موجود لكنه لم يشغل على GitHub. PGlite لا يختبر JWT أو اتصالات PostgreSQL متعددة، لذلك اختبرت الحالات الحساسة المذكورة أيضًا على الخدمات الحقيقية.

الاستيراد حتى ٥٠٠ صف والتصدير حتى ١٠٠٠ سجل في الصفحة، وتقارير الترتيب حتى ٥٠ نتيجة واختيار الأقسام حتى ٥٠٠ في بعض النماذج. لا worker/outbox عامل أو تكامل Bella أو تأكيد InstaPay تلقائي. التفاصيل في [دليل التشغيل](operations.md).
